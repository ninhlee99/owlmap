Architecture overview

The big picture: main components, how data moves between them, and the outside services they depend on.

A monolithic Rails app with three areas: accounts, billing and notifications.

  • Requests enter through config/routes.rb and are handled by controllers under app/controllers.
  • Business rules live in app/services, not in models.
  • Background work runs on Sidekiq: MailerJob, InvoiceJob.
  • External services: Stripe (payments), SendGrid (email), S3 (uploads).

Key flows

Step-by-step traces of the paths that matter most, with a diagram you can paste into any Markdown viewer.

Signing in

POST /login→SessionsController#create→User.authenticate→AuthService→SessionStore

Failed attempts are counted in Redis; after five, the account is locked for 15 minutes.

lib/billing

One note per module: its job, what it depends on, and what to be careful with.

Creates invoices at the end of each billing period and retries failed charges.

Depends on Stripe, Invoice, InvoiceJob.

Careful: tax rates are hard-coded in two places. Change both together.

Onboarding guide

A first-day reading order and the questions newcomers usually ask.

  • Read app/services/auth_service.rb first. Most features pass through it.
  • Run locally: bin/setup, then bin/dev.
  • Where are emails defined? In app/mailers, sent from MailerJob.

How it works

  1. Paste a repository link

    Any public GitHub repository up to about 500 source files during the beta.

  2. OwlMap reads the code

    Claude summarises each module, then pieces together the architecture and main flows. Usually a few minutes.

  3. Read or download the docs

    Browse them in OwlMap, or download Markdown files to commit next to your code. Written in English, Vietnamese or Japanese.
